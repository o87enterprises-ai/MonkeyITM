# Findings, 2026-10-10

From a read of commit `b311257` (merge of PR #7) by the owner's side, before the
independent review. Every finding below has a file:line and, where it was fixed, the
patch that fixed it. "Open" means the shape is stated in `docs/THREAT_MODEL.md` and
left for the reviewer.

## Fixed in this pass

### F1 - `Group::recv` did not check `alive`

`broker/src/group.rs:137`. `send` refused when the target had exited; `recv` drained
whatever was in the inbox. It worked today only because `set_exited` clears the inbox
(`group.rs:77-82`), so the liveness invariant lived in one place. If `set_exited` ever
stops clearing (e.g. to keep a dead agent's last messages in the log), `recv` starts
returning queued messages past exit.

Fix: `recv` returns `Err("{from} has exited")` when `!me.alive`, matching `send`.

### F2 - A missing process id made the child kill a silent no-op

`broker/src/spawn.rs:188`, `:235-238`. `child.id().unwrap_or_default()` produced
`pgid = 0` when tokio returned `None`; `kill_group` early-returns on `0`. The child
stayed in the running map, appeared in `running_children()`, and could never be
killed by `stop_children`. Same failure shape as the documented "if `kill` is
missing the kill silently does nothing", one layer up.

Fix: if `child.id()` is `None`, kill the child directly, remove the socket, mark the
group entry exited, and return an error instead of registering it.

### F3 - Capability tokens were minted for group actions that never use them

`broker/src/lib.rs:351-353`. `mint()` ran on every `Allow`, so `send_message`,
`recv_message` and `spawn_agent` each produced a signed token that was returned to
the agent (`v.token = Some(wire)`) and then discarded: `used.insert(nonce)` runs only
inside `exec::execute`. Tokens for those actions are not exploitable (they are
bound to the intent id and only `exec::execute` consumes them), but they are handed
out and never spent.

Fix: skip mint for routed actions. `v.token` is `None` for them.

### F4 - A log failure after the action ran left no verdict row

`broker/src/lib.rs:384-395`. When `record_result` failed, the code `return`ed a deny
without writing the verdict row. The action had already executed (write, exec,
http_get, child spawned, message queued) but the log showed an intent with no
verdict, and the tripwire count was skipped. The file's own doc comment says "if
any log write fails, the broker fails closed"; it did not hold here.

Fix: on result-log failure, set `v` to deny and fall through. The verdict row is
written, the tripwire counts, the agent sees a deny, and the log records the reason
as `log failure after the action ran: ...`.

### F5 - A log failure on the verdict row skipped the tripwire count

`broker/src/lib.rs:408-415`. If `record_verdict` failed, the code returned a deny and
skipped `count_denial` (step 5). An attacker who can induce SQLite write failures
(fill the disk, lock the file) could send denials forever without the wire firing.

Fix: on verdict-log failure, `drop` the log guard, call `count_denial()`, then return
the deny. A denial that cannot be logged still counts.

### F6 - A FIFO under an allowed read prefix could block a blocking-pool thread

`broker/src/exec.rs`, the free `read_file`. `File::open(&canon)` ran before the
`is_file()` check. A FIFO under `/tmp/safe/` (an allowed prefix) would make `open`
block forever on a `spawn_blocking` thread. Low severity - the agent has no
filesystem, so this needs an operator or a same-user attacker - but it is a DoS on
the broker's blocking pool if `/tmp/safe/` is ever shared.

Fix: open with `O_NONBLOCK`; `fstat` via `metadata()` still rejects non-regular files.

## Open, now in the threat model

### O1 - The socket trust boundary is filesystem permissions, not peer credentials

`broker/src/lib.rs:534` (root socket) and `broker/src/spawn.rs:156` (child sockets).
No `SO_PEERCRED` check. Any process running as the broker's user can connect to any
agent's socket and speak as that agent. `scripts/group-attack-test.py` itself does
this from the test process and treats it as normal.

The threat model should say so and argue it: same-user code execution is game-over
anyway, so a `SO_PEERCRED` check that only verifies "same UID as the broker" buys
nothing. A real fix needs per-agent UIDs, which is a bigger change than this pass.

### O2 - Malformed or oversized intent lines bypass the tripwire

`broker/src/lib.rs:617-630` (TooLong) and `:653-660` (unparseable). Both paths build
a `Verdict { verdict: Deny }`, write it to the socket, and continue - without
`decide_as`, without a log row, without `count_denial`. A client can send garbage
forever: no log, no halt. Bounded by bandwidth only; memory is fine because the
line reader drops the buffer on overflow.

A fix is a design decision, not a mechanical one - should a line that does not parse
count as a "denied request"? The tripwire is described as counting denied requests.
Argue it in the threat model or make the counter public and call it here.

### O3 - Broker shutdown may not record every child exit

`broker/src/lib.rs:542-550`. The `ctrl_c` handler calls `stop_children()` and
`return`s. The tasks that record `agent_exited` are `tokio::spawn`'d
(`spawn.rs:203-224`) and never awaited. On a clean `Ctrl-C`, children die but the
exit rows may be missing. The handoff calls this a "run-harness gap"; the harness
cannot fix it. A proper fix retains the waiter handles (or a `JoinSet`) and drains
them before returning.

### O4 - `Broker::register_agent` bypasses the group cap

`broker/src/lib.rs:229-234`. `pub` method that calls `group.add` with no size check;
`spawn_inner` enforces the cap separately under the group lock. Used only by
`broker/tests/messages.rs`. Now `#[doc(hidden)]` and documented as test-only.
Stronger fix (rename, move the test, `pub(crate)`) is a small follow-up.

### O5 - Shutdown and tripwire kill every child, not just the new one

`broker/src/spawn.rs:227-230`. `spawn_inner` calls `self.kill_all()` when the halt
fired during a spawn, which SIGKILLs every pre-existing child too. Safe but broader
than the new child; not documented. `docs/MULTI_AGENT.md` implies it under "the
tripwire and broker shutdown kill every group"; make it explicit in the code comment.

## Closed after this pass (branch `hardening/socket-and-shutdown`)

A code check of the six fixes above confirmed each is present (`group.rs:142`,
`spawn.rs:188`, `lib.rs:360-375`, `lib.rs:398-409`, `lib.rs:427-435`, `exec.rs:223-233`).
Three of the open items turned out worse than stated, or cheaper to fix, and are now
closed. Each has a check in `scripts/group-attack-test.py`, and each of those checks
fails against the pre-hardening build (`1e2d1f6`).

- **O1, socket permissions (worse than stated).** The argument above covers same-user
  access but not the umask: the root socket's mode came from the broker's umask, and
  under umask 0 it was `0777`, so any local user could connect and act as `a1` (observed
  on `1e2d1f6`). Fix: `bind_private` in `broker/src/lib.rs` creates the socket inside a
  fresh 0700 directory, sets it to 0600 and renames it into place; helper sockets use the
  same path. The umask is not touched (it is process-wide; a first version that changed
  it broke a directory created by another thread, caught by the Rust tests). A
  `SO_PEERCRED` check is still not done; per-agent UIDs remain the real fix for
  same-user attackers.
- **O3, shutdown (worse than stated).** Only Ctrl-C (SIGINT) was handled. SIGTERM, what
  `kill`, systemd and Docker send, ended the broker without stopping the children: a
  helper kept running, the root socket was left behind, and no exit was recorded
  (observed on `1e2d1f6`). Fix: SIGINT, SIGTERM and SIGHUP all go through one
  `shutdown` that kills every child, waits up to 5 s for each exit row, records a
  `shutdown` run event with the signal, and removes the socket. A `kill -9` of the
  broker cannot be handled and records nothing, but helpers no longer outlive it:
  a sandboxed helper already died with it (`--die-with-parent`, checked with the real
  sandbox on the build before this change too), and a helper under any other launcher
  was left running until `PR_SET_PDEATHSIG` was added (checked: fails before, passes
  after).
- **O2, garbage lines (decided).** An oversized or unparseable line is now logged as a
  `malformed_request` run event under the sending agent and counts toward the tripwire.
  The agent never sends one, so it is a fault or probing either way.

Closed afterwards (branch `hardening/attack-gaps`): O4 (`register_agent` renamed
`register_agent_for_tests`), O5 (scope of `kill_all` documented in code). Test-surface
gaps now covered: garbage and oversized lines (part 6), two helpers writing to one
mailbox at once (part 7), `kill -9` of the broker with a plain helper (part 8) and with a
real bubblewrap helper (part 9), and the hardcoded rule list replaced by a default-deny
helper allow-list. Not applicable: token capture and replay, because a request has no
token field (tokens go out in replies and are consumed only inside the broker).
Still open: the stand-in helpers in parts 1 to 8 do not exercise `run-child.sh` (only
part 9 and `multi-agent-test.py` do), and a slow `approve_required` request in flight
while another connection trips the wire.

## Test-surface gaps in `scripts/group-attack-test.py`

The script is strong but not exhaustive. These are the checks it does not make:

- It only sends parseable JSON. No garbage, no oversized lines. O2 is untested.
- It connects to a child's socket from its own process. That demonstrates O1 but
  the check "helper cannot start a helper" passes for the wrong reason: any
  same-user process could speak as the helper.
- The stand-in children are `scripts/idle-child.sh`, so the test exercises the
  broker's spawn path but not the real `run-child.sh` sandbox. `multi-agent-test.py`
  does test the real sandbox; the attack script does not.
- No token capture and replay: the script never grabs a `token` from an allow and
  tries it on another action or another socket.
- No concurrency: two agents sending to the same mailbox at once, or a slow
  `approve_required` request in flight while another connection trips the wire.
- No broker crash test: `kill -9` the broker with a live child and inspect the
  log on restart.
- The "no allowed helper request broke a rule" check is a hardcoded list
  (`group-attack-test.py:202-206`). A new action added tomorrow is not covered.

## What this pass did not change

Per-child policies (still one policy file per broker), the depth-1 spawn limit,
the `openat2` parent-directory-swap issue, the same-policy approval flow for the
root agent, the model-provider retry set (429/502/503/504 only; 500 and
transport failures still fail closed), and the `kill` shell-out. All remain as
stated in the handoffs.
