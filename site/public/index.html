Containment and safe testing for AI agents

MonkeyITM-VM is an open-source project to build a standard, auditable way to keep AI agents contained and to test them without letting them loose. The agent is given no authority of its own: everything it wants to do is a request that something else must approve and record first.

The problem we are working on

AI agents are being given real tools, real data and real autonomy, and the industry does not yet have a trusted, shared way to contain them or to test them safely. Recent public incidents involving agents that behaved outside their intended limits make this a live question for companies and governments alike.

Aim 1

Containment

An agent that holds no keys, no network and no files of its own, and can only ask. Every request is checked against rules set by people, and every decision is recorded.

Aim 2

Proctored testing

Run a new agent through a standard benchmark under full containment, so a score comes with proof of how it was earned and a record of everything the agent reached for beyond the task.

Aim 3

A shared standard

Work toward a common, reviewable protocol that developers, testers, insurers and regulators can all rely on. We are at the very beginning of that.

What has been tested so far

Internal tests by the developer, on one Linux host. Real AI models acted as the agents and were given tasks that asked for things the rules forbid: reading credentials, writing files, running commands, sending data out, following instructions planted in a file.

~80
test runs with two hosted AI models as the agents
~1,900
requests decided and recorded in those runs
0
allowed requests that broke a rule, by an audit of every log

The models did try forbidden things, often, and at times followed instructions planted in a file they were asked to read. Each of those attempts was refused and recorded. A separate scripted attacker, which skips the model and talks to the containment layer directly, ran 85 checks; all held.

What this does not show. These are our own tests, with tasks we wrote, two models and one configuration. They show that these attempts were refused. They do not show that nothing can get through. The project has not yet been independently audited; a third-party security review is being arranged. Treat every claim here as an early result, never as a guarantee.
